# 10 - 常见问题与陷阱

汇集 Fgui 开发中反复踩到的坑与经验。大部分来自真实调试记录。

## 1. 编译类

### 1.1 `utf8_to_codepoints_noexcept` 重定义

```
redefinition of 'std::vector<unsigned int> utf8_to_codepoints_noexcept(...)'
```

**原因**：`Fgui_includes.hpp` 先包含 `DebugText.hpp`（内部定义了 `utf8_to_codepoints_noexcept`），后包含 `decode.hpp`（同样定义该函数），只有 `decode.hpp` 先被包含时才会跳过 DebugText 的定义。

**修复**：任何源文件必须在 `#include "Fgui\Fgui.hpp"` **之前**先：

```cpp
#include "decode.hpp"
```

### 1.2 `#error Dont use fast_gui(the old version of fast_gui) with Fgui`

同时包含了旧版 `fast_gui.h` 与 `Fgui.hpp`。移除旧版头文件即可。

### 1.3 `Fgui_Control` 是抽象类，无法 `make_shared`

自定义控件**必须实现全部四个纯虚函数**：`ActionOnPaint` / `ActionOnEvent` / `ActionOnTimer` / `ActionOnGetTypeName`。漏掉任何一个都会导致抽象类错误。

### 1.4 启用二维码模块

需要：

```cpp
#define ENABLE_QRCODE_MODULE     // 必须在包含 Fgui.hpp 之前
#include "decode.hpp"
#include "Fgui\Fgui.hpp"
```

并在 CMake 中加入外部源文件 `QR-Code-generator/qrcodegen.cpp`

## 2. 坐标类（最高发坑区）

### 2.1 绘制 vs 事件：`relative_rect` 语义不同

- **绘制**（`ActionOnPaint`）：`relative_rect` = 控件**屏幕绝对位置**（父原点 + 滚动偏移，**已含** `default_rect.xy` 的效果）。
- **事件**（`ActionOnEvent`）：`relative_rect` = 父容器原点 **减滚动偏移**（**不含** `default_rect.xy`）。

因此：

```cpp
// 绘制里：直接用
SDL_Rect draw_area = {relative_rect.x, relative_rect.y, default_rect.w, default_rect.h};

// 事件里：必须加 default_rect.xy 才是控件屏幕矩形
SDL_Rect draw_area = {relative_rect.x + default_rect.x,
                      relative_rect.y + default_rect.y,
                      default_rect.w, default_rect.h};
```

若在事件里漏加偏移，点击坐标会整体偏左上（典型表现：点滚动条变成选中文本）。

### 2.2 事件 vs 定时器：`relative_rect` 滚动偏移不一致

- `ActionOnEvent` 传的 `relative_rect` **已扣除滚动偏移**（屏幕坐标）。
- `ActionOnTimer` 传的 `relative_rect` **未扣滚动偏移**（内容坐标）。

因此**不要在 `ActionOnTimer` 里直接用 `relative_rect + default_rect.xy` 算屏幕位置**。正确做法：在 `ActionOnEvent` 顶部保存屏幕矩形到成员，`ActionOnTimer` 里复用（`ComboBox` 打开下拉框即用此模式）。

### 2.3 容器型控件的定时器必须传局部坐标

自定义容器控件（类似 `TabControl`）在 `ActionOnTimer` 里调用子容器的 `MaintainTimer` 时：

```cpp
// ✅ 正确：传局部坐标 {0,0,w,h}
child->MaintainTimer({0,0,child->default_rect.w, child->default_rect.h});

// ❌ 错误：传屏幕坐标会导致脏区被 clamp 空，内容区永不重绘
```

`ControlBox::TestInvalidateRect` 把汇总的子控件脏区当作**容器局部坐标**写入 `dirty_region`。传错坐标的典型表现：按钮点了逻辑生效，但没有任何视觉反馈（按下变色等），看起来"点不动"。

### 2.4 贴边控件触发滚动条

窗口底部/右缘贴边的子控件，其 `y+h` 或 `x+w` 比容器大 1px 就会让容器判定"内容溢出"并出现滚动条。贴边定位务必留余量或钳制，窗口级根容器可用 `SetShowScrollBars(false)` 关闭。

## 3. 事件/交互类

### 3.1 滚轮事件坐标错位

`SDL_Event` 是 union，滚轮事件里读 `button.x/y` 得到的是错位字段（`wheel.y`/`direction`）。**滚轮命中测试必须用 `SDL_GetMouseState` 取真实坐标**：

```cpp
int mx, my; SDL_GetMouseState(&mx, &my);
if(isPointInsideRect({mx,my}, rect)) ...
```

### 3.2 滚轮"双滚动"问题

根容器 + 嵌套容器 + InputBox 同时滚动。Fgui 用**滚轮消费标记**解决：

- 子控件实际滚动后置 `wheel_consumed = true`。
- 容器发现任一子控件已消费 → 自己不再滚动，并把结果继续向上报告。

自定义控件若要消费滚轮，记得在滚动后置 `wheel_consumed = true`。

### 3.3 弹窗交互的坐标空间

自绘弹窗（`PopupWindow`）内部交互，命中测试坐标必须与渲染坐标**同空间（逻辑坐标）**。物理↔逻辑换算要基于**真实客户区尺寸**（`GetClientRect`），不要用 SDL 的窗口/渲染器尺寸接口（对软件渲染器可能返回逻辑尺寸，导致 DPI 换算失效）。

## 4. 生命周期/内存类

### 4.1 `PictureBox` 不持有传入的 surface

构造 / `SetImage` 内部用 `SDL_DuplicateSurface` 复制，传入的 `SDL_Surface*` 可立即 `SDL_FreeSurface`。控件自身持有的副本在析构时释放。

### 4.2 回调捕获 `std::map` 元素引用

`OnChange` lambda 捕获 `[&d]`（map 元素引用）是安全的，只要不在该 InputBox 存活期内 `erase` 该元素。关闭标签时应先移除/停用回调再 `erase`。

## 5. 性能/行为类

### 5.1 动画开关影响行为

`enable_animation` 全局关闭（默认）时：
- 按钮/滚动条颜色**立即跳变**，无过渡。
- `ControlBox` 滚动**立即同步**（不平滑）。
- `Slider`/`ProgressBar` 数值**立即跳变**（`ema_val` 直接同步）。

需要动画时调用 `Fgui_ConfigControlAnimation(true)`。注意：某些视觉细节（如 `ComboBox` 下拉指示符）只在动画分支实现，关动画时不会绘制——确保你的控件**动画/非动画两个分支都实现**（当然如果你懒癌发作当我没说）。

### 5.2 隐藏控件要跳过渲染/事件/定时器

`SetVisibility(false)` 后，`MaintainEvent`/`MaintainTimer`/`MaintainRender` 开头都会直接返回。容器（`ControlBox`）在遍历子控件时也要跳过不可见控件，否则隐藏控件会持续产生脏区导致每帧全量重绘。

### 5.3 `timer_time` 分频

`timer_time == 0` → 每帧调用 `ActionOnTimer`；`timer_time = 500` → 每 500ms 调用一次（如 `InputBox` 光标闪烁）。需要每帧逻辑的控件务必确认 `timer_time` 为 0。
